# FolderSpec v2 设计文档：三栏界面、文件预览、分组注释

日期：2026-08-20
状态：已批准，待实现计划
前置：[2026-08-19 MVP 设计](./2026-08-19-folderspec-design.md)（本文继承其全部原则与不变量）

---

## 1. 背景

MVP 交付后用户在真实使用中提出五点。其中两点是缺陷，已单独修复并合入（拖回原父级导致节点消失、选中高亮溢出到右栏）。剩余三点是新功能，构成本设计：

1. 界面缺乏设计感，希望接近 VSCode 观感
2. 可点击的树行区域几乎占满整屏，比例失衡
3. 希望单击文本文件能像 VSCode 一样看到内容
4. 希望支持多选（Shift 区间、Ctrl 跳选）并对一批节点写**一条**注释

第 4 点是本设计的重心：它同时改动界面、`core` 的数据模型、**以及 `.folderspec.md` 的格式**——后者是 Agent 与手改者共同依赖的接口。

## 2. 已确定的决策

这些由用户在设计对话中逐条拍板，后续实现不得擅自更改：

| 决策 | 取值 | 备选与否决理由 |
|---|---|---|
| 布局 | 三栏：树 \| 内容 \| 注释 | 两栏页签切换（写注释时看不到文件）、两栏上下分（长文件只能看一小段） |
| 批量注释语义 | **"这群东西作为一个整体"** | 否决"各自都符合这句话"——那种语义应当编译成带 glob 的规则，与分组是两回事 |
| 分组命名 | 自动生成，可改名 | 否决强制手动命名（主流程摩擦）、否决匿名（成员变动时 diff 噪声大，Agent 无法引用） |
| 分组在文件里的位置 | 新增 `## 分组` 区，列出成员路径 | 否决节点标签 `[group:x]`（多重归属要打多个标签、改分组会动结构区 diff）、否决两边都写（同一事实存两份必然漂移） |
| 文件图标 | 精选内联 SVG，约 20–25 种 + 兜底 | Seti 图标字体亦可行（更像 VSCode），但固定色在深色主题下需额外处理，且体积大一个数量级 |
| 语法高亮 | Prism 核心 + 约 12 种语言 | 否决纯文本（与 VSCode 观感差距过大）、否决 Shiki（产物体积翻 4–5 倍） |

### 一条必须说清的限制

**VSCode 不把用户当前生效的 file icon theme 暴露给 webview。** 因此即使在 VSCode 宿主内，图标也只能由本扩展自带，与用户原生资源管理器里看到的图标**可能不一致**。这不是实现瑕疵，是平台约束，应写进 README。

## 3. 格式变更：`## 分组` 区

### 3.1 语法

````markdown
## 分组

```yaml
- id: parse-layer
  members:
    - src/parse/sections.ts
    - src/parse/structure.ts
  text: 这两个共同构成解析层，改一个必须同步看另一个
  severity: warning
```
````

### 3.2 校验规则

与既有的模板区、规则区**完全同构**——三个 YAML 区保持同样的严格度，不引入新风格。

| 字段 | 规则 |
|---|---|
| `id` | 必填，非空字符串，全局唯一；重复时报行号（与规则区拒绝重复 id 一致） |
| `members` | 必填，非空字符串数组，工作区相对 posix 路径 |
| `text` | 必填，非空字符串 |
| `severity` | 可选，`error` / `warning` / `advisory` |
| 未知字段 | **拒绝并报行号** |

区块缺失时 `groups` 为 `[]`；`groups` 为空时序列化**不输出该区**——与模板区、规则区的对称性一致，这是 round-trip 成立的前提。

### 3.3 成员不存在于磁盘时

与既有 `spec-only` 语义一致：照常显示、虚线呈现、**永不自动删除**。不为分组开例外。

### 3.4 自动 id 的推导规则

取所有成员的**最长公共父目录**的 basename。`src/parse/sections.ts` 与 `src/parse/structure.ts` → `parse`。若与既有 id 冲突，追加 `-2`、`-3`。无公共父目录（成员分散在根下）时用 `group`。

规则必须是纯函数且可复现，以便测试穷举。

### 3.5 与节点自身注释的关系

**互不覆盖，各写各的。** 一个节点可以同时：拥有自己的 `— 注释`、属于一个或多个分组。导出时结构区写节点注释，分组区写分组注释，两者在文件里是不同区域的不同行。

## 4. 数据模型与 Api

### 4.1 core 类型增量

```ts
export interface Group {
  id: string
  members: string[]        // 工作区相对 posix 路径
  text: string
  severity?: Severity
}
```

- `Spec` 增加 `groups: Group[]`
- `ViewNode` 增加 `groups?: string[]`

`ViewNode.groups` 是 `merge` 由 `Spec.groups` 反查得到的**派生值**，不落盘。这不违反 MVP 设计 §3.4「不存储不可重算的东西」——它压根不是存储。

### 4.2 Api 增量

```ts
'spec/setGroup':    { params: { id: string | null; members: string[]; text?: string; severity?: Severity | null }
                      result: { tree: ViewNode; dirty: boolean; id: string } }
'spec/deleteGroup': { params: { id: string }; result: EditResult }
'file/read':        { params: { path: string }
                      result: { kind: 'text'; text: string; truncated: boolean }
                            | { kind: 'binary' }
                            | { kind: 'too-large'; size: number }
                            | { kind: 'unreadable'; reason: string } }
```

`id` 为 `null` 表示新建并按 §3.4 自动取名，实际 id 由 result 返回。

现有的 `spec/annotate` 保持不变，继续服务单节点。

### 4.3 纯函数增量（`spec-edit.ts`）

```ts
setGroup(spec: Spec, id: string | null, members: string[], patch: GroupPatch): { spec: Spec; id: string }
deleteGroup(spec: Spec, id: string): Spec
deriveGroupId(members: string[], taken: ReadonlySet<string>): string
```

保持既有风格：纯函数、返回新 `Spec`、不改入参。

## 5. 界面结构

### 5.1 三栏骨架

```
┌──────────────┬────────────────────────────┬─────────────────┐
│ 工具栏（工作区路径 · 搜索 · 保存）                              │
├──────────────┼────────────────────────────┼─────────────────┤
│ 文件树        │ 文件内容（只读）              │ 注释区           │
│ 260px 可拖    │ 弹性                        │ 320px 可拖       │
└──────────────┴────────────────────────────┴─────────────────┘
```

每栏是独立 flex 子项，各自 `min-width: 0; overflow: hidden`。**树宽由容器实测（`ResizeObserver`）而非 `window.innerWidth` 减常量**——这从构造上消除了已修复的高亮溢出缺陷的成因，而不只是修补它的表现。

`ResizeObserver` 在 jsdom 中不存在，测试环境需回退到固定尺寸；实现时必须保证回退路径下树仍能渲染出行，否则依赖真实渲染的 App 测试会失效。

### 5.2 VSCode 观感的具体落点

| 项 | 值 |
|---|---|
| 行高 / 字号 | 22px / 13px |
| 缩进 | 每级 8px + 缩进引导线（竖直细线） |
| 折叠箭头 | 仅目录显示，固定 16px 槽位（文件不占位则行首会抖动） |
| 悬停 / 选中 | 悬停淡底；选中强调底；多选时每一行都上底色 |
| 图标 | 精选内联 SVG，颜色走 `--fs-*` 变量 |
| 新增表面色 | sideBar 背景、editor 背景、panel 边框三组 token |

新增 token 必须同时在 CLI 宿主的默认调色板与 VSCode 宿主的 `--vscode-*` 映射中定义，否则一侧会得到透明背景。

### 5.3 多选

- **Shift+单击**：在**当前可见的展开顺序**上做区间选择——所见即所选，而非磁盘顺序
- **Ctrl / Cmd+单击**：跳选切换
- App 状态 `selectedPath: string | null` → `selectedPaths: string[]`

### 5.4 右栏的两种形态

| 选中数 | 右栏内容 |
|---|---|
| 0 | 提示"在左侧选中一个文件或目录" |
| 1 | 单节点面板（注释 / 语义角色 / 约束强度），与 MVP 一致 |
| ≥2 | **分组面板**：分组名（自动填、可改）· 共享注释 · 约束强度 · 成员列表（可逐个移除） |

### 5.4.1 选中集与既有分组的对应关系（自查补充）

「≥2 个」这一格原本有歧义：如果选中的节点已经属于某个分组，面板是新建还是编辑？规则如下：

- 当前选中集**与某个既有分组的成员集完全相等**时，面板**编辑该分组**（分组名与注释回填）
- 否则面板**新建**一个分组，分组名按 §3.4 自动推导
- 若有多个分组的成员集完全相同，面板顶部列出这几个供选择，默认取文件中靠前的那个

判定用集合相等，与顺序无关。这条规则可提成纯函数单测，不依赖界面。

### 5.4.2 单选时也要能看见归属

选中单个节点时，面板底部以只读方式列出它所属的全部分组（id + 注释首行），每项可点击——点击即把选中集设为该分组的成员，于是按 §5.4.1 自动进入该分组的编辑形态。

这同时回答了「用户如何选中并编辑一个既有分组」：**不需要新的界面入口**，从任一成员进入即可。

失焦提交语义沿用 MVP：输入时只改本地状态，`blur` 才派发。理由不变——每次派发都要走 bridge、重编辑 `Spec`、重跑 `merge`、重建整棵视图树。

### 5.5 分组成员的可见性

格式方案的代价是结构区文本不携带成员关系。界面上补偿：

- 属于任意分组的行，行尾显示一个**分组色点**；节点属于多个分组时显示多个点
- 当前选中集恰好构成某个分组时，其全部成员整行高亮
- 色点可点击：点击即选中该分组的全部成员（等价于 §5.4.2 的入口）

### 5.6 中间栏

- **只读。** 本工具只写 `.folderspec.md` 一个文件；中间栏不会成为编辑器
- 文本文件：行号 + Prism 高亮
- 二进制、超过 1MB、读取失败：显示占位说明与原因，不读内容
- 目录：显示子项统计而非内容
- 内容跟随**最后点击的那个文件**；多选不打断预览

## 6. 安全与错误处理

### 6.1 必须一并修复的既有缺口

MVP 最终评审留下一条延期项：`scan()` 的 `subPath` 接受 `..`，实测可枚举到 `/`。当时的延期理由是「不可从用户输入触达」。

**`file/read` 的引入使该前提失效**——它首次让工具按前端传来的路径读取任意文件内容并回传。因此本设计包含：

- 为 `scan()` 与 `file/read` 统一加工作区边界校验，拒绝任何含 `..` 段的路径
- 校验在 `core` 内实现一次，两个入口共用，不在两处各写一遍

这不是搭车重构：是新功能把一个已知缺口变成了真实可达路径。

### 6.2 其余错误路径

| 情况 | 处理 |
|---|---|
| 分组区解析失败 | 与其余区块一致：报行号、整体进只读模式、**绝不覆盖用户文件** |
| 分组 id 重复 | 报第二次出现的行号 |
| 成员路径含 `..` | 解析期拒绝并报行号 |
| `file/read` 目标不存在或无权限 | 返回 `unreadable` + 原因，中间栏显示，不抛错 |
| 分组被清空到零成员 | 界面上删除该分组；手写的空 `members` 数组是解析错误（字段规则要求非空） |

## 7. 测试策略

沿用 MVP 的方法，重点在三处：

- **round-trip property test 必须扩展到分组**。`serializeSpec → parseSpec` 的严格相等属性是本项目最关键的不变量；生成器需产出随机 `Group[]`，并沿用既有的去重约束（id 唯一）
- **`deriveGroupId` 穷举测试**：公共父目录、无公共父目录、id 冲突递增
- **路径越界**：`scan` 与 `file/read` 各自拒绝 `..`，且用真实临时目录验证确实读不到工作区外的内容
- **UI**：多选的区间/跳选逻辑提成可单测的纯函数（沿用 `makeMoveHandler`、`matchesSearch`、`makeDisableDrop` 的既有模式），不依赖虚拟列表渲染

任何回归测试都必须做 RED/GREEN 实证——MVP 期间有十次测试无法侦测其目标缺陷的记录。
